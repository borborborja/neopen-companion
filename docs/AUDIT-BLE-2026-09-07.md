# Auditoría de cambios BLE, interfaz y F-Droid — 2026-09-07

Alcance: cambios locales preexistentes que inicialmente se habían dejado fuera de
la publicación. El usuario pidió auditarlos e incluirlos en GitHub. Se incorporan
a v0.23.4 (versionCode 37), junto a la auditoría Android↔web.

## Hallazgos corregidos

1. **ACK tardío de ajustes**: tras timeout, la cola permitía un cambio nuevo del
   mismo tipo y podía confirmar el valor equivocado. El protocolo no incluye id
   ni valor en el ACK. Ahora se abre una nueva sesión GATT, se leen ajustes reales
   y solo entonces se reanudan intenciones aún no enviadas. No se reintenta a
   ciegas el ajuste fallido; se conserva el error y el valor confirmado.
2. **Sesiones BLE mezcladas**: callbacks antiguos, reensamblador y cola de escritura
   podían sobrevivir a una reconexión. Los callbacks se serializan en el hilo
   principal y comprueban la identidad GATT; cada conexión recrea su estado.
   Cambiar a otro boli descarta intenciones pendientes del dispositivo anterior.
   Fallos de escritura/descriptor no se tratan como comandos enviados.
3. **Volcado prematuro o solapado**: los workers esperaban 2–3 segundos antes de
   importar y sincronizar. Ahora esperan la respuesta de lista y el fin del
   volcado, y pueden unirse a uno activo sin reemplazar su cola/buffer. Borrado e
   importación no se permiten durante una transferencia.
4. **Falsos éxitos**: lista ausente, timeout de nota o paquete no solicitado podían
   marcar un volcado completo o dejar datos parciales. Se rechazan frames de
   longitud incorrecta, se limita el reensamblado y se aborta el volcado incompleto
   sin contador ni callback de éxito, conservando la copia del boli.
5. **Room adelantado por sync/contador**: páginas y contadores se lanzaban en
   corrutinas independientes. Se ordenan en una FIFO y el sync espera su barrera.
   Si falla una página, el contador no se escribe; el siguiente lote puede
   reintentar. El widget respeta el modo LOCAL y devuelve retry si falla el trabajo.
6. **Cambio al IME**: se descartaba la página pendiente al entrar en vivo; ahora se
   entrega antes. La restauración offline pendiente no se pierde al fallar un ACK.
7. **F-Droid**: receta referida a versión/tag antiguos y salida calculada desde el
   directorio incorrecto. Se selecciona el módulo `neopen`, se usa v0.23.4/37 y se
   ignoran claves de release bajo `-Pfdroid`, evitando APKs firmados por accidente.

El payload de SETTING_CHANGE_RESPONSE se contrastó con `SettingChange()` de
`web_pen_sdk@0.7.9`, SDK oficial ya instalado en el proyecto web: tipo + resultado.
La receta sigue la [referencia oficial F-Droid](https://f-droid.org/en/docs/Build_Metadata_Reference/)
para `subdir`, `output` y `gradleprops`.

## Verificación

Comprobación local final: **71 tests** (42 de core y 29 de app), sin fallos.

- Tests puros de cola, listas, framing y DTOs en `:core`.
- Regresiones del gestor con Robolectric (temporizadores, solapamiento, respuestas
  tardías, frames inválidos), de persistencia FIFO y las 15 de outbox/delta con Room.
- Compilación completa `:neopen:assembleDebug` y compatibilidad `:live:compileDebugKotlin`.
- Variante `-Pfdroid :neopen:assembleRelease`, incluyendo prueba con variables de
  firma configuradas; comprobación del APK sin firmar.
- `checkApiContract`, `checkFileModes` y CI con emulador oficial API 34 antes del merge.

No se ha probado BLE físico, ni se ha solicitado alta en F-Droid, cambiado la
visibilidad de los repositorios o desplegado una instancia del servidor.
